# 버전·릴리스 및 롤백

## 버전 기준

패키지는 `MAJOR.MINOR.PATCH`, 릴리스 태그는 `vMAJOR.MINOR.PATCH`를 사용합니다. 현재 버전은 `0.3.0`이며 버전 관리 도입 기준은 `0.2.0`입니다. 과거 작업의 릴리스 날짜나 태그를 소급 생성하지 않습니다.

- PATCH: 오류 수정, 작은 호환성·운영 개선
- MINOR: 신규 기능 또는 기능 확장
- MAJOR: 안정 버전에서의 호환성 깨짐. `0.x` 단계에서 호환성 변경은 MINOR를 올리고 변경 내용을 명시합니다.

배포 리비전은 커밋 SHA이고 릴리스 버전은 해당 SHA를 가리키는 태그입니다. 동일 버전 태그를 다른 SHA로 강제로 옮기지 않습니다. 다음 수정은 새로운 버전으로 릴리스합니다.

## 커밋 규칙

독립적으로 설명할 수 있는 기능·수정 단위로 커밋합니다. `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `style` 접두사를 사용합니다. 학습 주차 대신 사용자 기능이나 변경 목적을 제목에 씁니다. 변경 사항은 `CHANGELOG.md`의 Unreleased에 기록합니다.

## 릴리스 절차

1. 변경 범위를 정하고 다음 버전을 결정합니다.
2. `package.json`과 `package-lock.json`의 루트 패키지 버전을 함께 변경합니다. `npm version <다음버전> --no-git-tag-version`을 사용할 수 있습니다.
3. Unreleased 내용을 새 버전과 실제 릴리스 날짜 아래로 옮기고, 미검증 항목과 호환성 제한을 명시합니다.
4. 아래 검사를 실행합니다. 로컬 빌드는 담당자가 실행하거나 Vercel 배포 결과로 확인합니다.

```bash
npm run format:check
npm run lint
npm run test:unit
npx tsc --noEmit
```

5. 변경 파일을 검토해 릴리스 커밋을 만들고 새 저장소 `main`에 푸시합니다. 전체 작업 폴더를 무조건 추가하지 않습니다.
6. 배포 성공 및 운영 문서의 점검 항목을 확인합니다. 실패하면 릴리스 완료로 기록하지 않습니다.
7. 검증한 커밋 SHA에 주석 태그를 붙여 같은 저장소에 푸시합니다. 버전 문자열은 실제 다음 버전으로 교체합니다.

```bash
git tag -a vX.Y.Z <검증한-커밋-SHA> -m "meeTeam Frontend vX.Y.Z"
git push sejong-frontend refs/tags/vX.Y.Z
```

`sejong-frontend`는 `https://github.com/sejong-meeteam/meeteam-frontend.git`를 가리키는 로컬 remote 이름입니다. 다른 환경에서는 `git remote -v`로 대상 저장소를 먼저 확인합니다.

## 롤백

긴급 장애 시 Vercel에서 마지막 정상 배포를 다시 Production으로 승격합니다. 변경 당시의 환경 변수와 백엔드 계약도 함께 확인합니다. 배포 롤백은 현재 Git `main`을 자동으로 되돌리지 않습니다.

코드에서도 수정이 필요하면 원인 커밋을 검토한 뒤 `git revert <커밋-SHA>` 또는 수정 커밋을 만들어 재배포하고 PATCH 버전을 올립니다. 공유된 `main`을 강제 푸시하거나 기존 릴리스 태그를 덮어쓰지 않습니다. 프론트 롤백은 DB 데이터나 백엔드 버전을 되돌리지 않습니다.

## 릴리스 기록

`0.3.0`은 관리 상태 갱신·알림 인증 스트림·비밀 Q&A 보호 및 MSW 통합 검증을 포함합니다. 실서버가 꺼져 있어 실제 계정 E2E와 장시간 SSE 수신은 미검증입니다. [검증 범위](service-verification.md)를 참고합니다.
