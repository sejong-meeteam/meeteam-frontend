# 테스트 및 컴포넌트 검증

## 검증 경계

단위·API 통합 테스트는 Vitest, 사용자 화면 흐름은 Cypress와 MSW, 공통 UI 상태는 Storybook에서 검증합니다. 실제 백엔드의 로그인·권한·DB 저장·운영 SSE 연결 성공을 보장하는 테스트는 아닙니다. 실서버 점검 항목은 [서비스 검증](service-verification.md)을 참고합니다.

## 실행

Node.js 24에서 `npm ci`를 실행합니다. 서비스 E2E를 시작하기 전에 일반 Next 개발 서버를 종료합니다. 두 서버가 `.next/dev`를 공유하므로 동시에 실행하지 않습니다.

```bash
npm run test:types       # 앱과 Cypress TypeScript 검사
npm run lint
npm run test:unit        # 단위 + MSW API 통합
npm run test:regression  # 기존 지원 흐름 회귀
npm run test:e2e         # Next 테스트 서버 시작 → Cypress → 서버 종료
npm run test:stories     # Storybook 시작 → Cypress + axe → 서버 종료
```

서비스 E2E는 `127.0.0.1:3005`, Storybook 검증은 `127.0.0.1:6006`을 사용합니다. 해당 포트를 비워 두고 두 브라우저 테스트 명령은 순서대로 실행합니다. Cypress 기본 브라우저는 설치된 Electron입니다. 최초 설치 시 Cypress 실행 파일 다운로드 및 운영체제 의존성이 필요할 수 있습니다.

직접 Cypress 화면을 사용하려면 별도 터미널에서 `npm run dev:e2e`를 실행한 뒤 `npx cypress open`으로 서비스 spec을 선택합니다. Storybook spec은 `npm run storybook`이 필요합니다.

일반 서비스의 프로덕션 빌드는 이 테스트 명령에 포함하지 않습니다. 배포 전 `npm run build` 검증은 별도로 수행합니다.

## 실제 서버 요청 차단

- `scripts/start-e2e.mjs`가 API 모드를 `mock`으로 고정하고 서버 측 API Origin도 로컬의 비서비스 포트로 덮어씁니다. 개발자의 `.env.local`에 실제 서버 주소가 있어도 E2E에서 사용하지 않습니다.
- 브라우저의 알려진 실제 API 도메인 요청은 Cypress에서 차단하고 테스트를 실패시킵니다.
- MSW는 정의하지 않은 API 요청을 실제 서버로 우회시키지 않습니다.
- 각 테스트는 저장소와 세션을 초기화하고 `mocks/fixtures.ts`의 독립적인 데이터를 넣습니다. 비밀번호는 데모 값만 사용하고 Cypress 입력 로그에서 숨깁니다.

`test:service`는 `test:unit`에 포함됩니다. 두 결과를 별도 테스트로 합산하지 않습니다. axe 검사는 지정된 스토리만 대상으로 하며 전체 서비스의 접근성 인증을 뜻하지 않습니다. 스크린 리더와 실제 기기 검토는 별도로 필요합니다.

## Storybook 유지보수

`stories/`에는 버튼, 입력·드롭다운, 모달·토스트·스켈레톤·빈 상태, 프로젝트·팀원·알림 카드를 실제 공통 컴포넌트로 구성합니다. 컴포넌트의 정상·오류·비활성·제출 중 상태를 함께 관리합니다. 외부 API에 의존하지 않습니다.

스토리의 고정 `id`는 Cypress 진입 경로이므로 변경 시 spec도 수정합니다. 입력 요소는 가능한 레이블·역할 또는 기존 `data-cy`로 찾고, 무조건적인 대기나 예외 무시는 추가하지 않습니다. 접근성 실패는 규칙 제외 대신 원인을 수정합니다.

## 실패 분석과 제한

실패 화면은 `cypress/screenshots/`에 남고 Git에는 포함하지 않습니다. 콘솔의 실패 assertion·axe 대상과 화면을 함께 확인합니다. 민감한 실제 계정이나 운영 데이터를 테스트 fixture에 넣지 않습니다.

모의 SSE 검증은 운영 프록시의 연결 유지 시간·재연결을 대신하지 않습니다. 개발 서버 기반 E2E이므로 최적화된 프로덕션 산출물의 동작은 별도 확인해야 합니다. 테스트가 통과해도 실서버 통합 검증 완료나 전체 코드 커버리지 100%로 기록하지 않습니다.

의존성 설치 과정의 `npm audit`에서 기존 Next.js 및 전이 의존성 보안 경고가 확인되었습니다. 이번 테스트 도입에서는 프레임워크 업데이트나 `npm audit fix --force`를 수행하지 않았습니다. 배포 전 별도 보안 업데이트와 회귀 검증이 필요합니다.
